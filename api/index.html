Endpunkte

Ort immer entweder über lat & lon oder über city (optional mit country). Jede Endpunkt-Seite liefert reines JSON. Mit &view=1 gibt es eine formatierte Ansicht mit Kopieren und Download.

Für Postman, curl & Programme

Die .html-Seiten rechnen im Browser – Programme ohne JavaScript erhalten dort nur HTML. Echtes JSON (application/json, CORS aktiviert) liefern die Endpunkte ohne .html, bereitgestellt vom Cloudflare Worker (lokal: npm run dev → Port 8787).

GET/api/times?lat=48.89&lon=8.70&date=2026-11-22&method=TURKEY
GET/api/times?city=Pforzheim&country=Germany&method=TURKEY
GET/api/calendar?lat=48.89&lon=8.70&month=2026-12
GET/api/qibla?city=Wien&country=Austria · /api/methods · /api

Fehler kommen mit passendem HTTP-Status (400, 404, 422, 502) und demselben JSON-Format.

Antwortformat & Fehler

Jede Antwort enthält status und endpoint, dazu entweder data oder error mit code und message. Zeiten, die es an einem Ort nicht gibt (z. B. im Polarsommer), sind null.

StatusCodeBedeutung
400missing_locationWeder lat/lon noch city angegeben
400invalid_lat · invalid_lonKoordinate fehlt oder außerhalb des Bereichs
400invalid_date · invalid_monthFalsches Format (YYYY-MM-DD bzw. YYYY-MM)
400invalid_method · invalid_madhabUnbekannter Wert – erlaubte Werte stehen in der Meldung
404city_not_foundStadt nicht gefunden
422timezone_not_foundKeine Zeitzone für den Ort
502geocoding_failedOrtssuche (Nominatim) nicht erreichbar

Hinweis: Die Seiten liefern JSON nur im Browser (JavaScript nötig) – curl oder fetch() erhalten nur das HTML-Gerüst. Für Browser-Automatisierung (z. B. Playwright) steht das Ergebnis als window.apiResult bereit. Die Ortssuche nutzt den öffentlichen Dienst Nominatim – bitte keine Massenabfragen.
